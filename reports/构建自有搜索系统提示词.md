# 构建自有搜索评分系统 - 任务提示词

## 背景总结

### 为什么需要自建

当前使用的 Tavily Search API 存在以下问题：

1. **天花板效应**：宽泛查询（如"餐饮行业ERP解决方案头部平台官网"）导致所有结果的 score 都堆在 0.99-1.0 区间，区分度消失
2. **评分不透明**：Tavily 的 score 衡量的是「搜索相关性」而非「内容可用性」，与我们需要的评估维度不同
3. **评分不可控**：无法定制评分权重，无法干预排名逻辑
4. **成本考虑**：API 调用有费用限制

### Tavily 核心能力拆解

Tavily 实际上做了以下工作：

```
输入: 用户查询词
  ↓
1. 搜索引擎检索 → 返回一批 URL+标题
2. 相关性评分（BM25/向量相似度）→ 给每个结果打 score
3. 去重 + 排序
4. 返回 {url, title, score, content}
```

### 已有的逆向分析结论

基于 9 组对照实验，我们发现：

```
score ≈ α·BM25(标题匹配) + β·向量相似度 + γ·域名权威性
```

- **BM25 主导**：精确词匹配时 score 逼近 1.0（天花板效应）
- **向量相似度**：6-8 位小数支持连续向量计算
- **天花板效应**：查询越宽泛，score 越趋向 1.0
- **中文 > 英文**：中文查询 score 平均高 7.5%

## 技术方案选择

### 方案A：轻量自建（BM25-only）

**工具选型**：
- 搜索引擎：Meilisearch 或 Elasticsearch
- 爬虫：Scrapy
- 评分：BM25 * 0.6 + 关键词命中 * 0.4

**优点**：快速搭建，代码量可控
**缺点**：没有语义理解，标题堆关键词时失效

### 方案B：混合检索（BM25 + 向量）

**工具选型**：
- 向量数据库：Qdrant / Weaviate
- Embedding：sentence-transformers（中文可用 shibing624/text2vec）
- 爬虫：自建
- 评分：BM25 * 0.5 + 余弦相似度 * 0.5

**优点**：语义理解更准确
**缺点**：需要部署向量数据库，技术复杂度更高

## 评分体系设计要求

我们需要的评分体系应包含以下维度（权重可调）：

| 指标 | 权重 | 说明 |
|------|------|------|
| **可用率** | 40% | 非乱码、非导航内容的结果比例 |
| **内容质量** | 30% | 页面内容充实度、正文长度 |
| **域名多样性** | 15% | 结果来自多少独立域名 |
| **新鲜度** | 15% | 内容发布时间 |

**不应**：仅以「查询与标题的关键词匹配度」作为核心评分标准

## 第一步建议

先在一个小规模场景上验证：

1. 选择一个行业（如"餐饮ERP"）
2. 爬取 100 个相关页面
3. 用 Meilisearch 建小索引
4. 测试评分效果，对比 Tavily 结果
5. 根据对比结果调整权重
